# Первый запуск SubGuard внутри Telegram

Для первого теста сервер и собственный домен не обязательны. Приложение уже работает
на вашем компьютере; временный HTTPS-туннель делает его доступным из Telegram.
Эта инструкция выполняется **на вашем компьютере**, где работает Docker Desktop.
Публичное развёртывание и фактическая отправка сообщений пока не проверены.

## 1. Создайте бота

Откройте официального [@BotFather](https://t.me/BotFather) → `/newbot`.
Укажите отображаемое имя, затем свободный username, заканчивающийся на `bot`.
BotFather выдаст токен. Сохраните его приватно; не отправляйте в чат, скриншоты или GitHub.
При случайной публикации отзовите его через BotFather и выпустите новый.

## 2. Убедитесь, что приложение работает локально

Docker Desktop должен быть запущен. В папке с `compose.yaml`:

```powershell
docker compose up -d
```

Откройте `http://localhost:8080`. Сохраните копию своей `.env` перед изменением настроек;
не создавайте новую базу и не меняйте POSTGRES_PASSWORD/JWT_SECRET существующей установки.

## 3. Получите временную HTTPS-ссылку

Установите официальный Cloudflare Tunnel client. На Windows с winget:

```powershell
winget install --id Cloudflare.cloudflared -e
```

После установки откройте новый PowerShell и запустите:

```powershell
cloudflared tunnel --url http://localhost:8080
```

Программа напечатает временный адрес вида `https://случайное-имя.trycloudflare.com`.
Используйте **реальный адрес из вывода**, а не этот пример. Окно оставьте открытым.
Документация сервиса: https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/

Откройте полученную ссылку на телефоне, чтобы проверить доступность приложения.
Ссылка публична: не оставляйте туннель включённым после теста. Пользовательские API
по-прежнему требуют авторизацию; демо создаёт отдельные аккаунты.

Quick Tunnel — временный сервис без гарантии доступности. Если адрес не появился,
проверьте сообщения cloudflared и доступность сети. При наличии собственной конфигурации
cloudflared следуйте инструкции Cloudflare; не удаляйте её вслепую ради quick tunnel.

## 4. Подключите бота к приложению

В `.env` той же папки измените только следующие значения:

```dotenv
TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
MINI_APP_URL=https://ВАШ-АДРЕС.trycloudflare.com
CORS_ORIGINS=["https://ВАШ-АДРЕС.trycloudflare.com"]
```

Сохраните файл. Токен нигде не публикуется. Запустите профиль бота:

```powershell
docker compose --profile telegram up -d --build
```

Это пересоздаёт контейнеры с новыми настройками и сохраняет базу в прежнем томе.
Если открывается уже установленная версия, обновление образов не требуется, но команда
остаётся корректной. Для локального теста DEMO_MODE_ENABLED можно оставить true.

## 5. Откройте Mini App

Найдите своего бота по username в Telegram, откройте личный чат и нажмите **Start**
или отправьте `/start`. Бот должен прислать кнопку **SubGuard ↗**. Она уже реализована
в проекте и откроет сайт внутри Telegram.

Через эту кнопку приложение должно войти как Telegram-аккаунт, без надписи «Демо».
Записи из прежней браузерной демо-сессии автоматически не переносятся в ваш Telegram-аккаунт.

Дополнительно можно создать постоянную кнопку меню: в BotFather используйте
`/setmenubutton`, выберите бота и задайте тот же HTTPS-адрес и подпись «Открыть SubGuard».
Это удобство, а не обязательное условие работы кнопки из `/start`.

## 6. Проверьте уведомление

В приложении включите напоминания и установите правильный часовой пояс. Создайте
тестовую подписку с датой оплаты сегодня, вне тихих часов. Напоминания планируются
на 09:00 местного времени; если это время уже прошло, worker обработает актуальную
задачу при следующем цикле. Цикл — примерно 30 секунд, но доставка зависит от Telegram
и сети. До 09:00 сообщение не обязано прийти сразу.

Проверьте фактическое сообщение в Telegram и статус задачи в настройках. Не считайте
только статус запущенного контейнера доказательством доставки.

## Если бот молчит

```powershell
docker compose --profile telegram ps
docker compose logs --tail=50 bot worker api
```

Проверьте токен, реальный HTTPS-адрес и открытый туннель. Не запускайте одновременно
две копии polling-бота с одним токеном. Старый webhook может мешать polling; его нужно
отключать осознанно при переносе уже существующего бота. Перед отправкой логов скройте
токены и личные сведения.

## После теста

Ctrl+C в окне cloudflared остановит временный доступ. При новом запуске адрес обычно
изменится: обновите MINI_APP_URL/CORS_ORIGINS, пересоздайте сервисы и снова отправьте
`/start`; старые сообщения с кнопкой могут содержать старый адрес. Если настраивали
кнопку меню через BotFather, обновите её тоже.

Для постоянной демонстрации в портфолио нужен хостинг, работающий без вашего компьютера,
и устойчивый HTTPS-адрес. Практичный вариант — Linux VPS с Docker и 2 ГБ RAM или больше,
домен и HTTPS reverse proxy. Затем используйте DEPLOYMENT.md. Покупка сервера/домена
и публичное развёртывание в рамках этих инструкций не выполнялись.
