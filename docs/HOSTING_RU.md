# Постоянная работа SubGuard

SubGuard можно запустить на Linux-сервере с Docker Compose. Для Telegram Mini App нужен
постоянный публичный HTTPS-адрес. Файл `compose.production.yaml` добавляет Caddy, который
выдаёт TLS-сертификат и направляет запросы к веб-контейнеру. `compose.yaml` по-прежнему
отвечает за PostgreSQL, миграции, API, worker и бота.

## До запуска

1. Получить сервер с Docker и ресурсами, подходящими для PostgreSQL и сборки React.
   Для небольшой демонстрации ориентир — 2 ГБ RAM и 2 vCPU или больше; фактическая
   пригодность зависит от выбранной машины и нагрузки.
2. Получить стабильное имя хоста и направить DNS A-запись на публичный IPv4 сервера.
   Бесплатный поддомен возможен у некоторых DNS-провайдеров, но его доступность и
   правила нужно проверить отдельно. Сам по себе IP без домена не даёт надёжного TLS.
3. Открыть входящие TCP 80 и 443 в панели хостинга/межсетевом экране. Для Caddy HTTP/3
   можно также открыть UDP 443. Не открывать PostgreSQL-порт 5432.
4. Создать отдельные `POSTGRES_PASSWORD` и `JWT_SECRET` для сервера, не копируя с
   домашнего компьютера. Их значения вводятся только в серверный `.env`. Взять токен
   бота из BotFather; не публиковать его в репозитории и не отправлять в чат.
5. Если этот бот ещё запущен локально, остановить **только** локальный сервис бота:
   `docker compose --profile telegram stop bot`. Два polling-процесса с одним токеном
   будут мешать друг другу. Домашнюю БД это не удаляет.

## Пример серверного .env

После копирования `.env.example` в `.env` на сервере заполнить:

```dotenv
POSTGRES_PASSWORD=новое_случайное_значение_для_сервера
JWT_SECRET=другое_длинное_случайное_значение
APP_HOST=subguard.example.com
MINI_APP_URL=https://subguard.example.com
CORS_ORIGINS=["https://subguard.example.com"]
TELEGRAM_BOT_TOKEN=токен_бота_из_BotFather
ENVIRONMENT=production
DEMO_MODE_ENABLED=true
```

`subguard.example.com` — только пример; замените его своим реальным доменом. Если
публичный демо-режим не нужен, установите `DEMO_MODE_ENABLED=false`. Корневой
`.env.example` содержит подсказку `DATABASE_URL` для запуска без Docker; Compose
собирает нужный URL сам. Не вводите пароль в этот необязательный примерный URL.

## Запуск на сервере

На машине с Docker Compose v2 в каталоге проекта:

```sh
docker compose -f compose.yaml -f compose.production.yaml --profile telegram config -q
docker compose -f compose.yaml -f compose.production.yaml --profile telegram up --build -d
docker compose -f compose.yaml -f compose.production.yaml --profile telegram ps
```

Caddy получает сертификат через публичные центры сертификации. Выпуск может занять
несколько минут. Убедитесь, что имя хоста уже указывает на сервер, а TCP 80/443 доступны.
Проверьте `https://ВАШ_ДОМЕН/api/health`; ожидается `{"status":"ok"}`. Затем откройте
своего бота в Telegram, отправьте `/start` и нажмите SubGuard ↗. Проверьте вход и
фактическое получение тестового напоминания, а также состояние worker.

Логи конкретной службы:

```sh
docker compose -f compose.yaml -f compose.production.yaml --profile telegram logs --tail=100 https bot api worker
```

Порты веб-приложения на хосте ограничены `127.0.0.1:8080`; наружу приложение
публикует Caddy по 80/443. PostgreSQL не имеет внешнего порта. Файлы сертификатов
Caddy и данные PostgreSQL живут в отдельных Docker volumes. Не удаляйте их при
обновлении (`down -v` уничтожит данные).

## Резервные копии и обновление

Сначала сохраните резервную копию базы (команды в DEPLOYMENT.md) и проверьте её
восстановление на отдельной машине/БД. Затем обновляйте файлы репозитория и запускайте
ту же команду `up --build -d`. Сохраняйте серверный `.env` и Docker volumes.

Работа 24/7 зависит от самого сервера, его тарифа, сети и хостинга. Для платного VPS
это обычный сценарий; для бесплатных ресурсов проверьте лимиты, возможность
приостановки и правила поставщика. Этот репозиторий содержит конфигурацию, но
**не подтверждает наличие бесплатного сервера или уже выполненный публичный запуск**.

## Если нет карты и сервера

Текущий временный Cloudflare Quick Tunnel подходит для проверки, пока работает
домашний компьютер. Он не даёт постоянного адреса и работы при выключенном ПК.
Бесплатные веб-тарифы часто приостанавливают сервис при простое и могут не поддерживать
вместе Docker, PostgreSQL и фонового бота. Условия конкретного провайдера нужно
проверить до выбора; замена на такой тариф не будет полноценным 24/7.

Отдельный компьютер, работающий постоянно, можно использовать как домашний сервер
с постоянным туннелем и устойчивым именем, если это позволяют сеть и условия сервиса.
Это остаётся зависимым от домашнего питания и подключения.
